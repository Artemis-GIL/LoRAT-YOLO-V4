# B+D 实际执行框架

本说明依据正式 Test420 的冻结源码，不以最新工作区的后续实验覆盖它。

**当前帧 RGB → LoRAT 局部提议 + 同步 YOLO → B 默认决策和分组候选池 → D 的短历史相对质量比较 → 连续确认 → 保留 B 或替代输出/提交。**

B 使用已微调 LoRAT-L/378，保留 V3 输出分离基础控制。D 从 LoRAT 联合特征构建四个 1024 维描述子，并结合元数据及相对默认框的几何量；每 8 帧保存快照，每次查询读取最多三个过去快照及当前观察。GRU 状态每次查询重新从零开始，覆盖最多 24 帧，不是贯穿整段视频的长期递归记忆。

网络为候选预测定位质量，并减去默认动作质量形成相对分数。只有替代候选优势为正，且连续三帧满足共同分支和几何连续性，才替换 B。等待时执行 B 原决策，B 自身仍可恢复。短历史分支 ID 不是身份标签；建议选择不等于实际接管。

首帧模板固定；反向验证、MVLM 语言、Mamba 和 E 空间残差均未启用。训练脚本保留同阶段对照代码，是为了保存依赖和复核，而非声明最终推理使用了所有模块。

正式选择：`results/test420/parent/SELECTION.json`。正式权重：`provenance/WEIGHTS.json`。

测试结果属于整套 B+D，不能将与 V4 的所有精度/速度差归为 D 的单因素收益。开发 Val132 已参与选择，其消融记录和 Test420 必须分开引用。
